## 1. Session Focus

The primary objective of today's engineering session was to launch **ConversationKit vNext** on the newly created `develop` branch. Modern conversational AI interfaces have evolved far beyond plain Markdown request-response text bubbles into transparent, multi-step agentic workflows. Our goal was to design and implement an Apple-native SwiftUI architecture supporting intermediate chain-of-thought reasoning traces, tool execution groups, multi-step task checklists, human-in-the-loop permission gates, grounded source citations, rich onboarding welcome chips, and contextual composer controls—all while strictly preserving ConversationKit's core invariants:
1. Zero regression on the native **"Push and Pin" optimistic UI scroll physics** (`optimisticUserMessage` deduplication and `.top` scroll anchoring).
2. **Zero-breakage cooperative task cancellation** with the token-guarded turn coordinator.
3. **Stratos Progressive Disclosure** ergonomics, enabling a 1-line call site (`ConversationView(messages: $messages)`) to scale smoothly to complex agentic interfaces without forced downcasting.

## 3. Technical Decisions

1. **Single Outer Scroll Identity Contract**:
   - Every message turn retains a single outer `.id(ConversationScrollID.message(message.id))`. Sub-surfaces (`ThinkingStateView`, `ToolCallsGroupView`, `AgentPlanView`, etc.) mutate their internal heights strictly inside this container and never register competing `ScrollViewTargetLayout` IDs, preserving the "Push and Pin" scroll anchoring contract.
2. **Stratos Four-Layer Progressive Disclosure**:
   - *Troposphere*: Minimal 1-liner `ConversationView(messages: $messages)` continues to work out of the box with zero boilerplate.
   - *Stratosphere*: Fluent declarative modifiers for welcome configuration, composer models, capabilities, and turn callbacks.
   - *Mesosphere*: Automated rendering of agentic models when populated on `Message` types via `MessageView`.
   - *Thermosphere*: Standalone public components usable in custom view builders.
3. **Token-Guarded Turn Coordinator (`activeTaskID` / `coordinatorID`)**:
   - Prevented race conditions between asynchronous turns by tagging each execution with a unique token. Late `defer` cleanups from cancelled tasks can never nil-out an active turn's `sendingTask` or optimistic message state.
4. **Chameleon Cross-Platform Abstraction**:
   - Strictly isolated all `UIKit` and `AppKit` imports inside `Platform/PlatformTypes.swift`, exposing cross-platform semantic tokens (`PlatformImage`, `Color.platformSecondaryBackground`, `Color.platformGray4`, `PlatformPasteboard`).
5. **Equatable View Boundaries**:
   - Conformed `MessageView` and `EquatableMarkdownText` to `Equatable`, shielding the view hierarchy from gratuitous diffing passes while tokens stream into sibling rows.

## 4. Blockers & Resolutions

| Blocker / Hazard | Root Cause | Engineering Resolution |
| :--- | :--- | :--- |
| **Markdown Re-Parsing Hitch at 120Hz** | High-frequency token streaming caused MarkdownUI parser to re-evaluate the entire syntax tree on every character chunk. | Wrapped `Markdown(text)` in an `EquatableMarkdownText` leaf component comparing `text.utf8.count` first, eliminating redundant re-parses when text remains unchanged. |
| **`ScrollViewReader` Reset on Environment Changes** | Passing raw closures through SwiftUI `EnvironmentValues` changed closure identities on every view body re-render, triggering complete scroll view invalidations. | Introduced nominal wrapper types conforming to `Equatable` using a stable `@State private var coordinatorID = UUID()`, stabilizing the environment identity. |
| **`AsyncImage` Layout Jitter** | Remote images streaming in Markdown had unbounded initial bounds, causing sudden layout expansion when image dimensions resolved mid-scroll. | Constrained `AsyncImage` with explicit `maxWidth: 260, maxHeight: 280` and fixed `ProgressView` placeholder dimensions (`80x80`), reserving layout space up front. |
| **Rapid Turn Cancellation Race Condition** | Rapidly cancelling a generation and tapping retry caused the cancelled task's `defer` block to execute after the new task started, nullifying the new `sendingTask`. | Implemented token-guarded coordination checking `activeTaskID == currentTaskID` before clearing turn state in `defer`. |
