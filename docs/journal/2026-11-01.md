## 🔑 Key Breakthroughs & Technical Decisions
1. **Zero External Dependencies (`Package.swift`)**: Removed third-party Markdown and UI dependencies in favor of a native, deterministic block parser and `AttributedString` renderer in `StreamingMarkdownView.swift`, eliminating supply-chain overhead and strict-concurrency warnings in downstream apps.
2. **Optimistic UI & Top-Pinned Scroll Physics (`ConversationView.swift`)**: Combined synchronous optimistic user message insertion (`optimisticUserMessage` deduplicated by `Message.id`) with SwiftUI's `.scrollPosition` targeting `anchor: .top` and a dynamic trailing spacer (`activeTurnSpacerID`). This guarantees zero-jitter top pinning ($\Delta Y = 0.0\text{pt}$) while streaming responses expand downward.
3. **Nominal Action Wrappers for `@Entry` Environment Keys (`ConversationEnvironment.swift`)**: Wrapped closure callbacks in nominal `Sendable` structs (`SendMessageAction`, `ApprovalResponseAction`, `MessageActionsConfiguration`, etc.) to satisfy Swift 6.2 strict concurrency and eliminate `@Entry` closure warnings.
4. **First-Class Agentic Primitives & Style Protocols**: Designed composableSwiftUI `Style` protocols (`UserMessageBubbleStyle`, `MessageComposerStyle`, `ThinkingStateStyle`) paired with Liquid Glass materials (`.glassEffect`) so host applications can customize every surface without forking timeline views.

---

## 🚧 Blockers & Resolutions
- **Scroll Jump / Micro-Delay During Async Send**: Appending user messages asynchronously inside `onSendMessage` previously introduced a 1-frame delay during keyboard dismissal that disrupted `.top` scroll anchoring. Resolved by introducing synchronous `optimisticUserMessage` state with ID-based deduplication in `displayedMessages` plus a dynamic bottom turn spacer.
- **External Dependency Footprint in Demo Projects**: Removed stale `MarkdownUI` package references from `ConversationKitDemo` and migrated demo targets cleanly to the built-in v2 `StreamingMarkdownView` and `ConversationKit` v2 APIs.
