## 📜 Active Project Rules

### agentic-ui-physics

# Rule: SwiftPieces-Grade Agentic UI & Micro-Interaction Physics

1. **Auto-Expand / Auto-Fold Lifecycle**:
   - `ThinkingStateView` and `ToolCallsGroupView` must open automatically while active (`.thinking` / `.running`) and fold smoothly into compact summary rows (e.g., `"Thought for 3.2s"`, `"Used 4 tools · 3.2s"`) once completed.
2. **Live Monospaced Timers**:
   - Elapsed durations for thinking states, tool execution, and long-running agent runs must use `TimelineView` paired with `.monospacedDigit()` to prevent horizontal layout jitter.
3. **Welcome & Prompt Chips Handoff**:
   - Starter chips and welcome cards must appear when `displayedMessages.isEmpty` and support smooth spring transitions when populating the composer or submitting immediately.
4. **Accessibility & Simulator Verification**:
   - Preserve and extend stable `.accessibilityIdentifier(...)` tags on all interactive controls so `ConversationKitDemoUITests`, FlowDeck, and RocketSim can inspect and automate every pattern state.

### chameleon-cross-platform

# Rule: Chameleon Cross-Platform Abstraction & OS Availability

1. **Zero Raw UIKit/AppKit Types in Views**: Never reference `UIImage`, `UIColor`, `NSImage`, or `NSColor` directly inside `Sources/ConversationKit/Views/**`. Always route platform-specific types and color/symbol helpers through `Sources/ConversationKit/Platform/PlatformTypes.swift` (`PlatformImage`, `Color.platform*`).
2. **Compiler & OS Guards for Liquid Glass & FoundationModels**: Guard iOS 26+ APIs (such as `GlassEffectContainer`, `.glassEffect`, or `FoundationModels`) with both `#if compiler(>=6.2)` and `if #available(iOS 26.0, macOS 26.0, *)`, providing graceful material fallbacks for iOS 17+ and macOS 14+.

### optimistic-ui-scroll-contract

# Rule: Optimistic UI & "Push and Pin" Scroll Physics Contract

1. **Synchronous Optimistic Insertion**: When the user submits a message, `optimisticUserMessage` must be set synchronously in the same transaction as keyboard dismissal so `.scrollPosition` / `ScrollViewReader` can anchor the new user message with `anchor: .top`.
2. **ID-Preserving Deduplication**: `displayedMessages` deduplicates `optimisticUserMessage` against `messages` by comparing `Message.ID`. Any new message block (thinking, tool calls, citations, streaming chunks) must preserve stable `ConversationScrollID.message(message.id)` identity so expanding/collapsing disclosures never break the scroll anchor.
3. **Cooperative Cancellation**: While `onSendMessageAction` executes (`sendingTask != nil`), the composer's Send button must transform into a Stop button that invokes `sendingTask?.cancel()`.

### stratos-progressive-disclosure

# Rule: Stratos Progressive Disclosure (vNext API Evolution)

1. **Four-Layer API Scaling**:
   - **Troposphere (1-Line Default)**: `ConversationView(messages: $messages)` must always work out-of-the-box with sensible defaults.
   - **Stratosphere (Modifier Configuration)**: Expose view-level customizations (e.g., `.conversationStarters(...)`, `.thinkingStyle(...)`, `.toolCallPresentation(...)`, `.composerModes(...)`, `.messageActions(...)`, `.conversationDisclaimer(...)`) via `@Entry` on `EnvironmentValues` and public `View` modifiers.
   - **Mesosphere (Slot / ViewBuilder Injection)**: Allow custom SwiftUI `@ViewBuilder` closures for specific sub-surfaces (welcome header, thinking state, tool call rows, message bubbles, composer accessory bars).
   - **Thermosphere (Protocol & State Control)**: Expose full protocol conformance (`Message`, `Attachment`) with default protocol extensions so simple adopters only implement core fields while advanced agentic apps opt into `thinking`, `toolCalls`, `citations`, `plan`, and `approvalRequest`.
2. **No Boolean Traps**: Never add multiple boolean parameters to `ConversationView.init`. Use semantic enums, option sets, or dedicated view modifiers.
