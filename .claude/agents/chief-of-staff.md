## 📜 Active Project Rules

### chameleon-cross-platform

# Chameleon Cross-Platform Architecture

1. Centralize all UIKit / AppKit differences (`PlatformImage`, pasteboard, thumbnail generation via `ImageIO` / `QLThumbnailGenerator`, colors, haptics) inside `Sources/ConversationKit/Platform/`.
2. Domain models and SwiftUI views outside `Platform/` must compile cleanly on both iOS 26+ and macOS 26+ without scattered `#if canImport(UIKit)` blocks where a platform abstraction belongs.

### liquid-glass-composer

# Native iOS 26+ Liquid Glass & Composer Chrome

1. Target iOS 26+ and macOS 26+ natively using `GlassEffectContainer`, `.glassEffect(.regular.interactive(), in: ...)`, `.buttonStyle(.glass)` / `.buttonStyle(.glassProminent)`, `.buttonBorderShape(...)`, and `.safeAreaBar(edge: .bottom)`.
2. Never apply Liquid Glass inside scrolling `ScrollView` timeline cells; apply Liquid Glass exclusively to floating/pinned chrome (composer, first-turn suggestion chips, `/` and `@` autocomplete popup, and floating scroll-to-bottom button).
3. When the composer text field has focus (`@FocusState`), display a circular Liquid Glass keyboard-dismiss button (`keyboard.chevron.compact.down`) at the trailing edge of the input row inside the `GlassEffectContainer`.
4. Show suggestion chips on top of the input box only before the first user message is sent; once the first message is sent, animate them out cleanly.

### stratos-progressive-disclosure

# Stratos Progressive Disclosure & SwiftUI Style Protocols

1. Design all public APIs Call-Site First following the 4-layer Stratos Progressive Disclosure model (Troposphere drop-in defaults -> Stratosphere view modifiers -> Mesosphere composable subviews -> Thermosphere custom Style & protocol conformances).
2. Implement SwiftUI's native `Style` + `StyleConfiguration` pattern (`MessageComposerStyle`, `ThinkingStateStyle`, `UserMessageBubbleStyle`) so layout and visual styling are decoupled from state and behavior.
3. Provide strongly-typed `.onSendMessage` overloads so developers never need to downcast `any Message`.

### top-floating-scroll-physics

# Top-Floating Turn Scroll Physics & Non-Pushing AI Responses

1. When the user sends a message, the new user message immediately floats to the top of the screen (`anchor: .top`) via optimistic UI state in the same render transaction as keyboard dismissal.
2. The AI's response renders directly on the background below the user's message bubble.
3. If the AI's response grows longer than the screen height, it flows downward off the bottom edge and MUST NOT push the user's message up off the top of the screen.
4. Track scroll geometry via `.onScrollGeometryChange` with hysteresis (>80pt to show, <24pt to hide) to display the floating Liquid Glass scroll-to-bottom button whenever the user is not at the bottom of the chat.
